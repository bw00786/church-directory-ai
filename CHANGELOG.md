# Changelog

All notable changes to the Church Production Director. Versions follow
[semver](https://semver.org); the single source is `backend/app/version.py`
(`make version` checks `pyproject.toml` and `package.json` agree). Tag a release
with `git tag vX.Y.Z && git push --tags` to run the release workflow.

## 1.1.0 — 2026-10-30

A product-hardening release: the first version intended to be installed at a
second church. Upgrading from 1.0: run `scripts/setup-windows.ps1` (or
`python scripts/generate_secrets.py .env`) to add the new secrets, then review
the **Required settings** below. Schema migrations run at startup.

### Required settings (new)

- `API_KEY`, `API_ADMIN_KEY` — control-plane authentication. The backend binds
  to `127.0.0.1` by default; set `API_HOST=0.0.0.0` to serve the LAN.
- Real `POSTGRES_PASSWORD`, `SECRET_KEY` and a non-factory camera password:
  placeholders now refuse non-mock startup (`SECURITY_STRICT_STARTUP`).
- `EASYWORSHIP_AGENT_TOKEN` / `EW_AGENT_TOKEN` if you use the keystroke agent.

### Security
- API-key middleware with operator/admin roles on every route and WebSocket;
  public paths limited to health, docs and the UI bundle.
- Per-install secrets generated by setup; startup placeholder check; agent
  shared secret and IP allow-list; unknown `.env` keys reported at startup.

### Directing quality
- **Off-air PTZ staging.** Cues move the camera on preview and take it after
  settle; `transition` (cut/auto) and `cover_with` per cue. One role→preset
  table for the cue sheet, the AI and `move_to_role` (pastor preset 3).
- **Context sync.** The AI's context is kept current from ATEM, EasyWorship,
  VAD and cue-engine events (program, preview, who is speaking, plan cursor,
  time since last cut). Phase changes proposed by the LLM must clear a
  confidence gate and agree with a hard signal; the cue engine's state wins.
- **Pacing.** Hold, cooldown and consecutive-switch limits now apply to the AI
  path; cuts are held mid-sentence (speech boundary) and retried.
- **One proposal queue** with ids, TTL, supersede, source priority and
  effect-level dedupe against cue-engine actions; approve/reject by id with
  countdowns in the panel.
- **Prompt.** Delimited sections (timing, speakers, plan cursor, on air,
  vision, transcript with confidence, house rules, memory), shot grammar and
  worked examples, per-action confidence, structured JSON output. Director runs
  on the fast model with a 3 s deadline and backs off on Ollama outages.
- **Structured memory** with filtered retrieval and a deterministic house-style
  summary; adaptive confidence persisted per (category, state) from explicit
  operator feedback only.

### Learning and operator experience
- **Operator shot learning.** ATEM cuts and preset recalls the app did not
  command are recorded per (service part, speaker) with hold, transition and
  what was heard; they become the preferred role shot, raise the AI's minimum
  hold toward the operator's own pacing, and feed house-style bullets in the
  prompt. `GET /api/learning/*`.
- **Per-church rig profile** (`rig.yaml`): cameras and ATEM inputs, mixer
  channels per role, role shots, cue overrides/additions, order-of-service
  heading synonyms; `GET/PUT /api/rig`; one joystick panel per camera.
- **Setup wizard** on first run: discovery (ATEM, EasyWorship, Ollama),
  connectivity tests, audio device picker, writes allow-listed keys to `.env`.
- **Pause/Resume** the AI (operator key), **Rehearsal mode** replaying a
  recording through a private AI runtime with no hardware access, and a
  **Service review** page aggregating decisions, proposals, holds and cuts.

### Perception reliability
- Slide verification is tri-state; OCR outages never halt automation.
- Mixer meters expire when stale; disconnects read as silence.
- OCR, detection, diarization and Whisper run on dedicated thread pools; frame
  grab threads deliver fresh frames; detections cached per camera per tick;
  the legacy VisionManager never runs on test patterns.
- VISCA liveness, backoff reconnect, UDP sequence matching, ACK vs completion
  timeouts; ATEM `PROGRAM_CHANGED`/`PREVIEW_CHANGED` events, polled AUTO
  transitions, graceful mic-mute, real input ids in the mock, bridge tally.
- Audio: anti-aliased polyphase resampler with hardware timestamps, one Silero
  instance per channel (offline weights), Whisper confidence and 6 s flush,
  cross-channel bleed suppression, `is_singing` on transcripts.

### Operations
- `GET /health/ready` aggregates component health; UI status checklist and
  live readiness chip; ATEM **Undo** last cut; React error boundary; no demo
  data in the timeline.
- Canonical `/api/v1/...` paths (legacy prefixes still served); built UI served
  at `/app`; startup schema migration and `python -m app.database.cli migrate`.
- CI (backend, frontend, EasyWorship agent) and tag-driven release workflow;
  POSIX Makefile; ESLint; lean dependency core with `vision`, `audio`,
  `embeddings`, `voice` extras; `docs/install-windows.md`.

## 1.0.0

Initial single-church deployment: cue-sheet director, AI service director with
operating modes, line-by-line slide follower with operator slide-advance
learning, EasyWorship remote protocol, PTZOptics control, MGX16 USB audio,
voice attention, production memory.
